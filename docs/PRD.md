## 一、需求 (Requirements)

### 1.1 目标用户

**普通 KOC（独立内容创作者）**，月粉丝 1k–10w 量级，单兵作战，无 MCN 资源支持。典型画像：

| 维度 | 描述 |
|---|---|
| **职业身份** | 上班族 / 自由职业 / 在校生 / 宝妈，把短视频作为副业或转型路径 |
| **每日可投入** | 1–3 小时，难以应付 MCN 标准化的"选题—脚本—包装—互动"全流程 |
| **缺乏的能力** | 编导思维、爆款拆解经验、长尾 SEO 知识、评论运营策略 |
| **已具备的资源** | 一台笔记本、一个手机、对自身领域的真实经验 |
| **预算** | 极低，对 SaaS 月费 > 99 元已敏感 |

### 1.2 用户面对的三大痛点

| # | 痛点 | 痛感来源 |
|---|---|---|
| ① | **选题/创作焦虑** | 看到爆款视频只能"凭感觉模仿"，模仿出来的常常是表层而不是结构 |
| ② | **包装/分发缺位** | 写完脚本就没力气做标题/简介/标签了，长尾搜索流量持续被埋 |
| ③ | **互动/数据吃力** | 评论越多越焦虑，分不清高价值评论与灌水，回复语气也常出错 |

### 1.3 业务目标

| 类别 | 目标（v0.7 已达成） |
|---|---|
| **可用性** | 单兵创作者从 0 → 一份带有人设、脚本、发布元数据的内容产物，**用时 ≤ 30 分钟** |
| **产物质量** | AI 输出经 Pydantic 严校验（HTTP 422 拒绝畸形）；非空 / 长度 / 选项数 / 时间轴对齐 4 类硬约束 |
| **运营成本** | 后端单实例（4G 内存）、前端纯静态、ASR 占用 0 服务器 CPU（浏览器内 ffmpeg.wasm）；月度算力成本控制在 ≤ 100 元 / 单租户 |
| **可控收敛** | 引导式问答严格 **≤ 3 轮**（router 层 deterministic 拦截），用户决策疲劳被消除 |

### 1.4 范围边界（v0.7）

✅ 单平台短视频内容（不区分具体平台名）  
✅ 单租户、单浏览器本地存储  
✅ 文本 + 短视频 / 音频上传（同源 ffmpeg.wasm 抽轨）  
✅ DeepSeek 大模型（可一键切 mock）  
✅ 火山豆包大模型录音文件识别 · 极速版

❌ 多用户云端账号体系  
❌ 视频帧理解 / 画面级分析  
❌ 自动发布到平台 API  
❌ 实时弹幕互动

## 二、核心功能 (Core Features)

KOCopilot 由 **4 个对外功能模块** 组成，加 **1 个工作台** 做枢纽，加 **1 个底层基础设施层** 做支撑。

### 2.1 总览图

```
                      ┌──────────────────────────────────┐
                      │        index.html  产品说明        │
                      └───────────────┬──────────────────┘
                                      ↓
                      ┌──────────────────────────────────┐
                      │      workspace.html  工作台        │
                      │   KPI · 我的人设方案 · 我的脚本项目  │
                      └────┬───────────┬────────┬────────┘
                           ↓           ↓        ↓
                ┌───────────┐ ┌──────────────┐ ┌──────────────┐
                │ feature-2 │ │   feature-1   │ │  feature-3   │
                │ 人设生成    │→│   爆款拆解    │→│  标题车间     │
                └───────────┘ │  6 步工作流   │ └──────────────┘
                              └──────┬───────┘
                                     ↓
                              ┌──────────────┐
                              │  feature-4   │
                              │  评论分拣     │
                              └──────────────┘
```

### 2.2 模块一 · 人设生成（`feature-2.html`）

| 维度 | 实现 |
|---|---|
| **触发** | 用户填写 `职业 / 兴趣 / 资源` 三段背景 |
| **后端** | `POST /api/persona/generate`（DeepSeek） |
| **产出** | 1–5 个差异化人设方案，每个方案 7 个字段：<br>`name` / `differentiation` / `rationale` / `reference_accounts` / `onboarding_advice` / `monetization_outlook` / `score(1-5★)` |
| **存储** | 成功后**立即**入库 `localStorage["koc.personas.v1"]`（最多 30 条），出现在工作台「我的人设方案」 |
| **下游** | 在爆款拆解的「第 0 步」被引用为本次拆解的人设上下文 |

### 2.3 模块二 · 爆款拆解 + 脚本引擎（`feature-1.html` · 6 步工作流）

> **本模块是产品核心**。它把"对标爆款"转化为"属于你人设的原创脚本"，是其它模块的内容源。

| 步骤 | 功能 | 关键约束 |
|---|---|---|
| **第 0 步 · 选择人设** | 从工作台已保存方案中**显式**选一个，sessionStorage 持久化 | 防止"自动取最新"导致拿错；未选则不传 persona_hint |
| **第 1 步 · 输入对标内容** | 二选一 tab：① 上传视频/音频（浏览器内 ffmpeg.wasm 抽轨 → 豆包 ASR）② 粘贴台词 | 文件 ≤ 30 MB；台词 ≥ 20 字 |
| **第 2 步 · AI 拆解骨架** | `POST /api/skeleton/extract` 返回 `{hook, body[], cta, transferable_template}` | Hook 6 种策略枚举；CTA 5 种策略枚举；body 时间轴对齐 |
| **第 3 步 · 引导式问答** | `POST /api/qa/next` ≤ 3 轮单选；router 在 answers ≥ 3 时强收敛 `done=true` | 不开放自由输入；选项必须可朗读、有差异 |
| **第 4 步 · 原创脚本** | `POST /api/script/generate` → `{hook_narration, scenes[], cta_narration, full_text}` | scenes 时间轴必须与骨架 body 对齐 |
| **第 5 步 · 一键复制 / 带入** | 「复制纯文本」 + 「下一步：标题车间 →」（自动写 sessionStorage） | navigator.clipboard + execCommand 双轨保险 |

**只有走完第 4 步才入库**：完整记录 = 人设 + 台词 + 骨架 + 3 个答案 + 完整脚本，一次性写 `localStorage["koc.scripts.v1"]`。中途放弃**不**污染历史。

### 2.4 模块三 · 标题车间（`feature-3.html`）

| 维度 | 实现 |
|---|---|
| **触发方式** | ① 拆解完成自动跳转并填入 ② 工作台「带入标题车间」按钮 ③ 手动粘贴 |
| **后端** | `POST /api/seo/titles`（DeepSeek） |
| **产出** | `5 个标题`（含类型 / 字数 / 备注） + `视频简介（≤ 150 字）` + `标签矩阵（泛流量 + 精准长尾 + 话题挑战）` |
| **可交互按钮** | 「采用」复制对应标题 · 「复制简介」· 「换一版」重跑生成 · 「一键复制全部标签」 |
| **平台说明** | 当前面向通用短视频平台（Hook 前置 / 标签密度 / 强情绪规则） |

### 2.5 模块四 · 评论分拣（`feature-4.html`）

| 维度 | 实现 |
|---|---|
| **后端** | `POST /api/comments/classify`（DeepSeek） |
| **输入** | 多行评论文本（每行一条） |
| **产出** | `high_value[]`（含 3 种语气的回复草案：专业 / 幽默 / 共情）+ `medium_value[]`（含分类标签）+ `low_value_count`（仅计数，不展示） |
| **回复风格** | 系统 prompt 强约束"不写客套话、不重复评论原文" |

### 2.6 模块五 · 工作台（`workspace.html`）

| 维度 | 实现 |
|---|---|
| **KPI 卡** | 本周生成脚本 / 累计人设方案 / 待回复评论（运营接入后展示）/ 累计节省工时（按 1.5h × 脚本数） |
| **我的人设方案** | 默认收起一行摘要，点「展开 ↓」内联展示该记录里全部 personas[] + 起号建议 + 变现预判 |
| **我的脚本项目** | 默认收起，展开后展示选用人设 + 骨架摘要 + 3 答案 + 完整脚本（带滚动）；底部「复制脚本到剪贴板」「带入标题车间 →」「× 删除」 |
| **持久化** | 100% 客户端 `localStorage`，无服务端账号。最多各 30 条。 |

### 2.7 底层基础设施

| 层 | 实现 |
|---|---|
| **LLM 抽象** | `LLMClient` 协议；`MockLLMClient`（按 system prompt 内独占字段名做 fingerprint 路由 6 种 mock 输出）/ `DeepSeekClient`（OpenAI 兼容 SDK）；通过 `LLM_PROVIDER` 环境变量切换 |
| **ASR 抽象** | `ASRClient` 协议；`MockASRClient` / `DoubaoFlashClient`（火山豆包极速版 `volc.bigasr.auc_turbo`）|
| **Schema 校验** | Pydantic v2 严格校验所有 LLM 响应，畸形输出返回 HTTP 422，前端弹 toast |
| **跨源隔离** | nginx COOP/COEP 双 header；vendored `/vendor/ffmpeg/` 解决 Worker 同源约束 |
| **部署** | `scripts/deploy.sh` = git pull + venv pip + systemctl restart + 30s 健康检查 + 失败自动 rollback；版本受控的 nginx 站点配置；与慢病项目 `zlhu.asia` 独立证书共存 |

## 三、AI 能力 (AI Capabilities)

### 3.1 模型矩阵

| 能力 | 模型 / 服务 | 用途 |
|---|---|---|
| **大语言模型** | DeepSeek-V3 / R1（OpenAI 兼容协议） | 人设 / 拆解 / 问答 / 脚本 / SEO / 评论分拣 |
| **录音文件识别** | 火山豆包大模型录音文件识别 **极速版**（`volc.bigasr.auc_turbo`） | 把视频抽出的音轨转成台词文本 |
| **视频抽轨** | `ffmpeg.wasm 0.12.x` 浏览器内运行 | 0 服务器 CPU 把 mp4/mov 抽成 wav 发给 ASR |

### 3.2 Prompt 工程要点

每个模块都有独立的 system prompt，关键设计点：

| 模块 | Prompt 关键约束 |
|---|---|
| **人设生成** | 强制输出"差异化"而非"通用"标签；每个方案必须有具体 reference_accounts；星级评估写入 prompt 内提示词 |
| **爆款拆解** | Hook 6 策略 / CTA 5 策略枚举锁定；body 必须给出 emotion_arc；transferable_template 与原内容解耦（可复用结构） |
| **引导式问答** | 3 轮主题硬绑定（Hook / Body 切入 / CTA）；选项必须可朗读、禁开放式套话；选项之间必须有差异（角度 / 情绪 / 受众）；不允许照抄原视频台词 |
| **脚本生成** | scenes 数组长度必须 = 骨架 body 长度；scenes[i].timestamp 必须 = body[i].timestamp；3 个答案分别落地到 hook_narration / 中段 / cta_narration；硬性禁止照抄原视频台词 |
| **SEO** | Hook 前置 / 强情绪 / 标签密度规则；5 类标题（反常识/数字/身份/痛点/悬念）保证多样性；标签按"泛流量 + 精准长尾 + 话题挑战"三段 |
| **评论分拣** | 三种语气回复必须有可识别差异；客套话 / 重复评论原文 一律 ban |

### 3.3 确定性收敛策略

LLM 不可信，所以关键约束都同时写在 **prompt（软）+ router（硬）+ schema（终判）** 三层：

| 约束 | 软（prompt 提示） | 硬（router 拦截） | 终（schema 校验） |
|---|---|---|---|
| 引导式问答 ≤ 3 轮 | 在 system 里写"3 轮固定主题" | `if answered >= 3: return done=true 不调 LLM` | `MAX_QA_ROUNDS=3` 字段约束 |
| scenes 与骨架对齐 | 在 user message 里把 timestamp 列出来 | — | Pydantic min/max length |
| 选项 3-4 个 | "返回 3-4 个选项" | router 截断到 4 | `max_length=4` |
| 字段非空 | "禁止留空" | — | Pydantic `min_length=1` |

### 3.4 Mock 模式

`LLM_PROVIDER=mock` 时，`MockLLMClient` 通过 system prompt 内**独占字段名**做 fingerprint 路由：

| Fingerprint | 模块 |
|---|---|
| `personas` | 人设生成 |
| `transferable_template` | 爆款拆解 |
| `rationale` | 引导式问答 |
| `hook_narration` | 脚本生成 |
| `broad_traffic` | SEO |
| `low_value_count` | 评论分拣 |

mock 模式下整套流程可在零外部依赖下跑通（用于 CI / 离线演示 / 成本测试）。

```
│  │           ├ Round 1（Hook 角度）→ 单选                              │

│  │           └ Round 3（CTA 风格）→ 单选 → router 强收敛 done=true     │
│  ├── 第 4 步：自动 /api/script/generate → 渲染分镜脚本卡片              │
│  │           ★ 一次性入库（localStorage["koc.scripts.v1"]）            │
│  └── 第 5 步：点「复制纯文本」OR「下一步：标题车间 →」                    │
│                  ↓                                                    │
│  feature-3.html （标题车间）                                            │
│  textarea 自动带入脚本 → 点「生成发布元数据」                            │
│  → 5 标题 + 简介 + 标签矩阵                                             │
│  → 「采用」复制 / 「换一版」重跑 / 「复制全部标签」                       │
│                  ↓                                                    │
│  视频发布后                                                             │
│                  ↓                                                    │
│  feature-4.html （评论分拣）                                             │
│  粘贴评论文本 → 高价值评论 + 三种语气回复草案                             │
└──────────────────────────────────────────────────────────────────────┘
```

### 4.2 子流程 · 引导式问答的对话状态机

```
[IDLE]   骨架未生成 → 第 3 步面板显示「等待第 2 步骨架完成」，按钮 disabled
   │
   │ feature-1 第 2 步成功
   ↓
[READY]  按钮 enabled「开始 3 轮单选问答 →」
   │
   │ 用户点开始
   ↓
[ROUND_1]  POST /api/qa/next（answers=[]）
            → 后端注入「Hook 角度」主题 → DeepSeek 出 3-4 选项
            → 用户单击 → 选项立刻全部 disabled + 高亮选中
            → answers.push({round:1, q, choice})
   ↓
[ROUND_2]  POST /api/qa/next（answers=[a1]）
            → 后端注入「Body 切入」主题
            → 用户单击 → answers.push(a2)
   ↓
[ROUND_3]  POST /api/qa/next（answers=[a1,a2]）
            → 后端注入「CTA 风格」主题
            → 用户单击 → answers.push(a3)
   ↓
[DONE]   POST /api/qa/next（answers=[a1,a2,a3]）
            → router 拦截：返回 done=true（0ms 不调 LLM）
            → 自动触发 POST /api/script/generate
            → 第 4 步面板渲染脚本 + 启用「复制纯文本」
```

### 4.3 子流程 · 工作台历史可展开 / 可消费

```
workspace.html
   ↓ 一条「我的脚本项目」记录（默认收起）
   ↓ 用户点「展开 ↓」
   ┌─ 选用人设（来自第 0 步）
   ├─ 骨架摘要（Hook 文本 / Body 段数 / CTA 文本）
   ├─ 3 个创作决策（每条一行带 ✓ 标记）
   ├─ 完整脚本（带最大高度 280px 的滚动条）
   └─ 操作按钮：
       [复制脚本到剪贴板]  →  navigator.clipboard 复制
       [带入标题车间 →]    →  写 sessionStorage 后跳 feature-3
       [× 删除]           →  二次确认 confirm 后 removeScript(id)
```

### 4.4 错误处理

| 错误类型 | 现象 | 处理 |
|---|---|---|
| ASR 调用失败 | 视频上传后转写超时 | toast 提示 + 切到"粘贴台词"tab，引导手输 |
| LLM 调用失败 | 5xx / 429 / 网络抖 | toast 提示 + 卡片内嵌入 retry 按钮 |
| LLM 返回畸形 JSON | Pydantic 422 | 后端拒绝、前端 toast"返回字段不符合 schema" |
| LocalStorage 配额满 | 30 条上限触发 | 静默丢弃最旧；不阻塞主流程 |
| 浏览器无 cross-origin isolation | 视频 tab 不可用 | 上传按钮加 title 提示 + 推荐切到 mp3/m4a 直传或粘台词 |

## 五、使用场景 (Use Cases)

### 5.1 场景 A · 上班族转型短视频博主（典型 P0）

> 小李，互联网公司产品经理，月入 1.2 万，想做"职场反内卷"博主。每天通勤 1 小时 + 周末 2 小时是全部可投入时间。

**用 KOCopilot 的一天**：

| 时间 | 动作 | 工具 |
|---|---|---|
| 周六 9:00 | 在 workspace 点「+ 生成新人设」，填"产品经理 / 反内卷 / 1 部 iPhone" | feature-2 |
| 9:05 | AI 出 3 个方案，选「反内卷打工人 · 用产品思维拆穿职场骗局」 | 入库 |
| 9:10 | 进 feature-1，第 0 步选刚才的方案 | KOCActivePersona |
| 9:12 | 上传一个收藏的"反 996"对标视频，等 ffmpeg + ASR 转写 | feature-1 第 1 步 |
| 9:14 | 拆解骨架出炉（Hook 痛点前置 + Body 3 段 + CTA 评论区互动） | feature-1 第 2 步 |
| 9:16 | 答 3 题：① Hook 选"数字反差"② Body 选"实拍演示对比"③ CTA 选"打首字母" | feature-1 第 3 步 |
| 9:17 | 自动生成完整分镜脚本 1100 字 | feature-1 第 4 步 |
| 9:18 | 点「下一步：标题车间」自动带入；点生成 → 5 个标题 + 简介 + 标签矩阵 | feature-3 |
| 9:20 | 「采用」一个标题、「一键复制全部标签」、复制简介，去剪映 | 完成发布素材 |
| 周一晚 | 视频发布 24 小时，评论 50 条 → 复制粘贴到 feature-4 → AI 标 8 条高价值 + 给三种语气回复草案 | feature-4 |

**全程 30 分钟**完成一个原本需要 3 小时的工作流。

### 5.2 场景 B · 多账号矩阵运营（典型 P1）

> 老王同时运营 3 个差异化账号（职场 / 美妆 / 育儿），每个账号都需要独立人设与脚本。

| 痛点 | KOCopilot 解法 |
|---|---|
| 容易把 3 个账号的语气写串 | 第 0 步**显式选人设**，QA 与脚本生成的 prompt 都注入对应人设 hint |
| 历史脚本难找 | workspace「我的脚本项目」按时间倒序 + 标题预览 + 「展开 ↓」直接看完整脚本 |
| 改 prompt 调试成本高 | LLM_PROVIDER 切 mock 调试前端 → 切 deepseek 跑产线，改前端不影响 LLM 行为 |

### 5.3 场景 C · 离线 / 弱网演示（P2）

> 客户演示场地无外网；或带宽抖动严重无法访问 DeepSeek。

切 `LLM_PROVIDER=mock` + `ASR_PROVIDER=mock`：6 个 mock fingerprint 让所有 4 个模块走通完整 UI 流程，演示者不依赖网络。

### 5.4 场景 D · 个人服务器自托管（P2）

> 创作者已有一台私人小服务器（已运行其他项目），想加一个 KOCopilot 但不愿污染主项目。

`scripts/install-on-medi-server.sh` 自动：① server_name 隔离（互不干扰）② 独立 systemd 单元 ③ 独立 LE 证书 ④ 独立 nginx 站点。15 分钟落地。

## 六、产品价值 (Value Proposition)

### 6.1 核心价值主张

> **让一个人，干出一个 MCN 团队的产出质量。**

具体兑现为 4 个层次：

| 层次 | 用户感受 | 量化指标 |
|---|---|---|
| **效率价值** | 30 分钟完成原本 3 小时的工作 | ≈ 节省 6× 时间 |
| **质量价值** | 输出结构严密、不照抄、与人设贴合的原创脚本 | 引导式问答 100% 收敛在 3 轮内 |
| **学习价值** | 每个 AI 输出都附"为什么这样做"的方法论标签（Hook 策略 / CTA 策略 / 标签密度） | 用户使用 5 次后能独立看懂爆款结构 |
| **决策价值** | 高价值评论自动捞出 + 三种语气回复草案 | 评论运营从"凭感觉"到"有标准动作" |

### 6.2 与同类产品的差异化

| 维度 | KOCopilot | 通用 ChatGPT | MCN 内部工具 |
|---|---|---|---|
| 是否懂创作者业务 | ✅ 6 个独立 prompt 模板 | ❌ 通用对话 | ✅ 但封闭 |
| 是否强收敛 | ✅ router 硬限 ≤ 3 轮 | ❌ 用户决定 | 因人而异 |
| 是否可自托管 | ✅ 单机部署 | ❌ 强 SaaS | ❌ 不开放 |
| 是否本地存储 | ✅ 100% localStorage | 服务端 | 服务端 |
| 是否单平台锁死 | 通用短视频规则（不锁死特定平台） | 任意 | 多平台 |
| 是否带 ASR | ✅ 浏览器内同源 | ❌ | 部分有 |

### 6.3 商业化路径（v0.x 不启用）

| 阶段 | 模式 | 触发条件 |
|---|---|---|
| v0.x（当前） | **开源 + 自托管** | 当前阶段 |
| v1.x | 提供 hosted 单租户版（4G 实例约 50 元/月） | 单租户验证完成 |
| v2.x | 团队协作版（多用户、云端历史、prompt 微调） | 出现 5+ 个人客户主动询问"能否给团队用" |
| v3.x | API + 集成生态（接入剪映 / 万兴 / 第三方发布平台） | DAU ≥ 200 |

### 6.4 可观测的成功信号（北极星指标）

| 指标 | v0.7 实测 | 预期 |
|---|---|---|
| **30min 任务完成率** | 待埋点 | ≥ 70% |
